# Python packaging

> **Capa floor is Python 3.10; do not use features tagged 3.11+.**

Source PEPs (all Final): PEP 517 (build backend interface), PEP 518
(`[build-system]` requires), PEP 621 (`[project]` metadata), PEP 660
(editable installs), PEP 440 (versioning), PEP 508 (dependency specifiers),
PEP 751 (`pylock.toml` lockfile).

All packaging metadata lives in `pyproject.toml`. The facts below were read
from that file.

## Rules tied to Capa's pyproject

| Area | PEP | What Capa does | Rule for contributors |
| --- | --- | --- | --- |
| Build backend | 517 | `build-backend = "setuptools.build_meta"` | keep it; do not swap backends casually |
| Build requires | 518 | `requires = ["setuptools>=68", "wheel"]` under `[build-system]` | bump floors here, not elsewhere |
| Project metadata | 621 | declarative `[project]` table (name, version, description, `requires-python`, license, authors, classifiers, optional-dependencies, scripts, urls) | new metadata goes in `[project]`, never in `setup.py` / `setup.cfg` |
| Versioning | 440 | `version = "1.31.0"` | PEP 440 compliant; never `1.31.0-beta`, use `1.31.0b1` for pre-releases |
| Dependency specifiers | 508 | extras with markers, e.g. environment markers like `; python_version < "3.11"` | write dependencies and markers in PEP 508 form |
| Editable installs | 660 | `pip install -e .` via setuptools | supported; used in `CONTRIBUTING.md` setup steps |

Note: `requires-python = ">=3.10"` in `[project]` is the single source of the
floor these docs enforce.

## Lockfiles: PEP 751 `pylock.toml` (non-blocking decision note)

- PEP 751 defines `pylock.toml`, the **first standardized, tool-agnostic
  lockfile format** (Final). It is the first real lockfile *standard*.
- `requirements.txt` was **never a PEP**; it is an informal pip convention.
  Do not call it "the standard lockfile."
- Capa's CI currently uses **uv-generated, hash-pinned locks**
  (`requirements-test.lock`, `requirements-ci.lock`, regenerated by
  `scripts/relock.sh`; see `CONTRIBUTING.md`). These are uv's format, not
  necessarily `pylock.toml`.
- **Decision item (non-blocking)**: migrating to, or additionally emitting,
  `pylock.toml` would align with the new standard. The current uv locks
  work and gate CI today, so this is a standards-alignment choice, not a
  fix. Do not treat it as a required change.

## Discouraged

- Metadata in `setup.py`. Not banned, but PEP 621 declarative metadata is
  current practice and Capa is already fully declarative. Keep it that way.
