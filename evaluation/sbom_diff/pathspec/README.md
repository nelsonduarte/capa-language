# pathspec

A gitignore-style path matcher of the PyPI `pathspec` shape
(~50M downloads/month; `black`, `isort`, `mypy`, and basically
every Python repository walker depend on it for their
`--exclude` flags).

## What the library does

Tests whether a path matches a gitignore-style glob pattern:

1. Optional leading `!` flips the match.
2. Optional leading `/` anchors the pattern to the repository
   root.
3. Optional trailing `/` means "directory only".
4. `*` matches any run of characters (the naive Python excludes
   `/` for `*` and includes it for `**`; this subset treats `*`
   as a generic wildcard).
5. `?` matches exactly one character.
6. All other characters match literally.

The naive public API is
`matches_pattern(path: str, pattern: str) -> bool` and its
multi-pattern sibling
`matches_any(path: str, patterns: list[str]) -> bool`.

## Authority surface

*(none)* - pure string transformation; sits alongside slugify/,
tabulate/, textwrap/, humanize/, csv_parser/ as a pure-case in
the study.

## Why representative

Three reasons:

1. **It is heavily deployed.** The PyPI `pathspec` library pulls
   ~50M downloads/month and ships inside `black`, `isort`,
   `mypy`, `pre-commit`, and most other Python repo walkers.
   The shape of its public API is recognisable to anyone who has
   configured an `--exclude` glob.
2. **It is the first glob-matching pair in the corpus.** The
   other pure cases (`slugify/`, `tabulate/`, `textwrap/`,
   `humanize/`, `csv_parser/`) all do pure string transformation
   over flat character sequences; this pair adds a recursive
   pattern matcher to the pure-case panel. The Capa version
   proves the recursive matcher pure, with the same per-function
   attribution as the rest of the pure cases.
3. **It is the structural-asymmetry case taken further than
   slugify.** Capa has no regex stdlib at all, so the Capa
   version implements gitignore globbing DIRECTLY via recursion
   rather than reaching for an equivalent of `re.fullmatch`.
   The user-facing semantic is identical; the Capa SBOM shows
   that even without a regex library, the per-function purity
   claim holds for arbitrary text matching. The naive Python
   imports `re` (a capability-bearing module by category, but
   used purely here) and a PURL-based SBOM cannot distinguish
   "imports `re`" from "calls a regex compiler with attacker-
   supplied input"; Capa attributes zero capabilities per
   function and the compiler enforces it.

## Naive Python's PURL SBOM proxy

The top-level import block is `import re`. A PURL-based SBOM
generated by syft / pip-licenses for this file would list `re`
as a stdlib import, with no per-function attribution and no
signal that the function is pure. `re` is capability-bearing by
category (regex compilation is a non-trivial computation
surface), but the compiled pattern never escapes the function
body and no Fs / Env / Net / Stdio call is reachable from any
helper.

The Capa SBOM names zero capabilities for every helper and the
compiler proves it: a hidden Fs / Env / Net / Unsafe call in any
of `strip_anchors`, `is_negation`, `strip_negation`,
`glob_match`, `matches_pattern`, or `matches_any` would be
rejected at type-check time because no such capability is in
scope.

Note on glob scope: the Capa `glob_match` supports only `*`,
`?`, and literals. The naive Python additionally exposes the
`**` vs `*` distinction (any-char vs any-non-slash) via the
regex translation. The capability-attribution point this pair
makes is independent of the glob feature set; full gitignore
glob is a substantial undertaking and the simplified shape
demonstrates the per-function purity claim equally well.

Note on complexity: the recursive matcher runs in exponential
time on adversarial inputs. For the demo inputs (short paths
and patterns) it is instantaneous. Production glob engines
convert to NFA / DFA up front; the pedagogical naive recursion
suffices for the SBOM-diff harness.
