# secret_rotator

A "secret with TTL" rotator of the shape that every cloud-deployed
Python service that talks to a managed secrets store exposes
(`python-keyring` with caching, `aws-secretsmanager-caching` -
AWS's own client-side cache for SDK secrets - `pydantic-settings`
with `refresh_on` hooks, and `vaultenv`).

## What the library does

Reads a secret out of the process environment once, caches it in
memory, and refreshes it from the env after a TTL expires. The
public API is a pair:

1. `make_rotator(env_key, ttl_seconds)`: read `os.environ.get(env_key)`
   once, stamp the current wall-clock time as `cached_at`, and
   return the state holder. Exercises Env (read the secret) and
   Clock (stamp the cache).
2. `get_secret(rotator)`: read the wall clock; if the cached
   value is still within `ttl_seconds` of `cached_at`, return it
   without touching the env; else re-read the env, update the
   state in place, and return the fresh value. Exercises Env (on
   a cache miss) and Clock (on every call).

The freshness arithmetic itself (`now - cached_at < ttl`) is
pure given a `(cached_at, now, ttl)` triple; the state-update
that builds the new `(value, cached_at)` pair is pure too.

## Authority surface

`Env + Clock` exercised in `make_rotator` and `get_secret`; the
freshness check (`is_fresh`) and the state-update
(`refresh_state`) are pure.

## Why representative

Three reasons:

1. **It is ubiquitous.** Every cloud-deployed Python service that
   talks to a managed secrets store caches the result in memory
   to avoid hot-loop env reads (or hot-loop calls into the
   secrets manager that the env variable backs). `python-keyring`
   ships caching out of the box; `aws-secretsmanager-caching`
   exists solely to provide this primitive for the AWS SDK;
   `pydantic-settings` exposes `refresh_on` hooks for the same
   purpose; `vaultenv` covers the HashiCorp Vault side. Between
   them these libraries cover most production deployments where a
   secret is rotated out of band and the service has to pick up
   the new value without restarting. A capability-aware SBOM that
   handles this pattern correctly covers a structural component
   of essentially every Python service that consumes a managed
   secret.
2. **The pure / impure split is surgical.** The freshness
   decision (`now - cached_at < ttl`) is a pure function of
   `(cached_at, now, ttl)`; the state-update that builds the new
   RotatorState is a pure function of `(state, fresh_value, now)`;
   the ONLY impure parts are the single `env.get(...)` read and
   the single `clock.now_secs()` read at the top of `make_rotator`
   and `get_secret`. Capa exposes this split surgically (two
   functions are pure, two carry `Env + Clock`, one carries
   `Stdio`); Python rolls it all into `os` + `time` and two
   signatures that say nothing about which functions read the env
   or read the clock.
3. **It is the first `Env + Clock` combination in the corpus.**
   The existing pairs cover `Env` alone (`env_loader`), `Clock`
   alone (`rate_limiter`), and `Fs + Env` (`dotenv`); this pair
   adds the `Env + Clock` cell. Adding it widens the
   axis-combination coverage of the study by one cell and gives
   the harness a clean two-authority data point that does not
   touch the filesystem or the network.

## Functions

| Function | Signature shape | Declared capabilities |
|---|---|---|
| `is_fresh` | `(Float, Float, Float) -> Bool` | *(none)* |
| `refresh_state` | `(RotatorState, Option<String>, Float) -> RotatorState` | *(none)* |
| `make_rotator` | `(Env, Clock, String, Float) -> RotatorState` | `Env`, `Clock` |
| `get_secret` | `(Env, Clock, RotatorState) -> SecretResult` | `Env`, `Clock` |
| `main` | `(Stdio)` | `Stdio` |

## Naive Python's PURL SBOM proxy

The top-level import block is `import os` and `import time`. A
PURL-based SBOM generated by syft / pip-licenses for this file
would list `os` (a capability-bearing stdlib module that mixes
filesystem access, process control, and environment access under
one name) and `time` (a capability-bearing stdlib module that
mixes the wall-clock and monotonic-clock reads with pure helpers
like `time.strftime`). It would say nothing about which
functions read the env vs which read the clock; both authorities
are conflated under each of `make_rotator` and `get_secret`, and
the pure helpers `_is_fresh` and `_make_state` are invisible to
the PURL view as separately attributable units.

The Capa SBOM names both authorities per-function on
`make_rotator` and `get_secret`, attributes `Stdio` to `main`,
and proves the pure functions (`is_fresh`, `refresh_state`)
cannot touch either of them; the freshness check is pure given a
`(cached_at, now, ttl)` triple and the state-update is pure
given `(state, fresh_value, now)`.
