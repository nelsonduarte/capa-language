# humanize

A human-friendly number / duration / size formatter of the PyPI
`humanize` shape (~30M downloads per month).

## What the library does

Formats raw integers into user-facing strings by:

1. Picking a binary (1024-based) unit scale for byte counts and
   emitting one decimal place: `1536 -> "1.5 KB"`,
   `1500000 -> "1.4 MB"`.
2. Splitting a duration in seconds into hours / minutes /
   seconds, omitting zero parts and comma-joining the rest:
   `90 -> "1 minute, 30 seconds"`, `3600 -> "1 hour"`.
3. English-style pluralisation of a count: `(1, "file") ->
   "1 file"`, `(3, "file") -> "3 files"`.

The naive public API is `format_bytes(size: int) -> str`,
`format_duration(seconds: int) -> str`, and
`format_count(n: int, singular: str, plural: str | None = None) -> str`.

## Authority surface

*(none)* - pure number/string transformation; sits alongside
slugify/, tabulate/, and textwrap/ as a pure-case in the study.

## Why representative

Three reasons:

1. **It is universally deployed.** The PyPI `humanize` library
   draws ~30M downloads per month, and the pattern (byte counts,
   ETA strings, pluralised summaries) is present in essentially
   every CLI tool that prints user-facing metrics. The shape of
   its public API is recognisable to any Python programmer.
2. **It is the arithmetic-heavy pure-case in the study.** Unlike
   `slugify` and `textwrap`, the work is shaped around integer
   division, modulo, unit-scale branching, and pluralisation
   rather than string transformation. This exercises Capa's
   number-to-string and branching paths in a way the other pure
   cases do not, broadening the structural coverage of the
   pure-baseline slice.
3. **It is the PURL-silence case at the limit again.** The naive
   Python has no imports at all, not even `typing`. A PURL-based
   SBOM for the file says literally nothing about the file's
   behaviour. The Capa version, by contrast, names every helper
   and declares zero capabilities per function, with the
   compiler proving each one pure.

## Naive Python's PURL SBOM proxy

The top-level import block is empty: `naive.py` imports nothing.
A PURL-based SBOM generated by syft / pip-licenses for this file
therefore says nothing beyond "depends on Python itself", with
no per-function attribution and no signal that the functions are
pure.

The Capa SBOM names zero capabilities for every helper and the
compiler proves it: a hidden Fs / Env / Net / Unsafe call in any
of `format_count`, `format_scale`, `format_bytes`,
`join_commas`, or `format_duration` would be rejected at
type-check time because no such capability is in scope.

Note on scope: Capa does not yet support default parameter
values at the function-signature level, so `format_count` takes
an explicit `plural: String` argument where the Python defaults
to `None` and computes `singular + "s"` internally. Callers pass
the plural form explicitly. The `format_bytes` one-decimal
output is built from integer arithmetic only (`tenths = (size *
10) / divisor`) to avoid a `Float` conversion; the naive Python
uses the same trick. The capability-attribution point this pair
makes is independent of both choices.
