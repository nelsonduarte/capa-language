# dotenv

A `.env` file loader of the python-dotenv shape (~3M downloads
per month on PyPI).

## What the library does

Reads a `.env` file (lines of `KEY=VALUE` with `#` comments and
optional surrounding quotes), parses it into a dict, and
overlays the result onto the process environment. The public
API is `load_dotenv(path: str = '.env', override: bool = False)
-> dict`.

## Authority surface

`Fs + Env` exercised inside one function; signature declares
none of them.

## Why representative

Three reasons:

1. **It is widely deployed.** python-dotenv is one of the most-
   downloaded Python libraries; many Python services include it
   in production.
2. **The shape conflates Fs and Env under one signature.** Same
   structural failure as `config_loader`'s `load_config(path)`:
   the function reads the disk AND mutates global state, but the
   signature names neither authority.
3. **It surfaces an asymmetry between Python and Capa that goes
   beyond per-function attribution.** Capa's `Env` capability is
   read-only by design (it has `env.get` but no `env.set`), so
   the Capa transliteration cannot mutate global state at all.
   The Capa version returns a `Map<String, String>` that the
   caller threads forward. The SBOM-diff for this pair is not
   only "Capa attributes per-function while PURL does not"; it
   is also "Capa structurally forbids the global-state mutation
   that the Python version performs as an implicit side effect".

## Functions

| Function | Signature shape | Declared capabilities |
|---|---|---|
| `parse_env_text` | `(String) -> Map<String,String>` | *(none)* |
| `strip_surrounding_quotes` | `(String) -> String` | *(none)* |
| `load_dotenv_file` | `(Fs, String) -> Result<Map, IoError>` | `Fs` |
| `merge_with_env` | `(Env, Map, Bool) -> Map` | `Env` |
| `load_dotenv` | `(Fs, Env, String, Bool) -> Result<Map, IoError>` | `Fs`, `Env` |
| `main` | `(Stdio)` | `Stdio` |

## Naive Python's PURL SBOM proxy

The top-level import block is `import os`. A PURL-based SBOM
generated by syft / pip-licenses for this file would list
`os` (a capability-bearing stdlib module). It would say nothing
about which functions exercise file I/O vs which mutate the
environment.

The Capa SBOM names both authorities per-function and proves the
pure functions (`parse_env_text`,
`strip_surrounding_quotes`) cannot touch either.
