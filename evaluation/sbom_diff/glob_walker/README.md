# glob_walker

A recursive file-walker of the `glob.glob("**/*.py", recursive=True)`
(Python stdlib), `pathlib.Path.rglob("*.py")` (Python stdlib),
and `pathspec` (PyPI) shape.

## What the library does

Walks a directory tree recursively and returns the full paths
of every file whose basename ends with a given suffix. The
public API is `find_files(root: str, suffix: str = ".py") -> list[str]`.

## Authority surface

`Fs` only, and only in `walk_dir`; the suffix matcher and the
path helpers are pure.

## Why representative

Three reasons:

1. **It is universal.** Every linter, formatter, type checker,
   packager, build system, and ad-hoc maintenance script walks
   a directory tree and selects files by name. The pattern is
   ubiquitous enough that the Python stdlib ships two modules
   for it (`glob` and `pathlib.Path.rglob`) and a popular PyPI
   library (`pathspec`) on top.
2. **It is the second Fs-only pair in the corpus, but a
   different Fs method mix.** Both this pair and `ini_loader/`
   carry the same `capa:declared_capability=Fs` string in their
   per-function SBOM rows, but the runtime authority they
   exercise is different: `ini_loader` uses `fs.read` (the
   file-content side of Fs); `glob_walker` uses `fs.list_dir`
   and `fs.is_dir` (the directory-walk side). The `Fs`
   capability is one type from the SBOM consumer's perspective,
   but the underlying surface is two distinct method groups, and
   `Fs.restrict_to` attenuates both: a caller that hands
   `fs.restrict_to("/tmp/")` into `walk_dir` bounds the walk to
   `/tmp/` regardless of which Fs methods the callee picks.
3. **The PURL SBOM names capability-bearing modules but cannot
   attribute them.** The naive Python imports `os` and `glob`
   (both stdlib, both capability-bearing). A PURL-based SBOM
   generated by syft / pip-licenses for this file would list
   both as components and would say nothing about which
   function exercises the disk. The matcher and path helpers,
   which are pure, would be bundled into the same SBOM row as
   the walker. Capa narrows `Fs` to `walk_dir` per-function and
   proves the matcher and path helpers cannot touch the disk.

## Functions

| Function | Signature shape | Declared capabilities |
|---|---|---|
| `matches_suffix` | `(String, String) -> Bool` | *(none)* |
| `basename` | `(String) -> String` | *(none)* |
| `join_path` | `(String, String) -> String` | *(none)* |
| `walk_dir` | `(Fs, String, String) -> Result<List<String>, IoError>` | `Fs` |
| `main` | `(Stdio)` | `Stdio` |

## Naive Python's PURL SBOM proxy

The top-level import block is `import glob` and `import os`. A
PURL-based SBOM generated by syft / pip-licenses for this file
would list `os` and `glob` (both capability-bearing stdlib
modules) as components, with no per-function attribution. It
would say nothing about which function exercises file I/O, and
the pure helpers (`_matches_suffix`, and the implicit
`os.path.join` calls) would be bundled into the same SBOM row
as the walker.

The Capa SBOM names `Fs` per-function on `walk_dir` and proves
the pure helpers (`matches_suffix`, `basename`, `join_path`)
cannot touch the disk.
