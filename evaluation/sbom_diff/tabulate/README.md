# tabulate

An ASCII-table formatter of the PyPI `tabulate` shape (~50M
downloads per month on PyPI).

## What the library does

Formats a list of rows (each row a list of cells) as a fixed-
width ASCII table, padding each column to the width of its
widest cell and drawing `+---+---+` separator lines around the
header and below the body. The naive public API is
`tabulate(rows: list[list], headers: list | None = None) -> str`.

## Authority surface

*(none)* - the library is purely a string transformation; this
pair sits alongside `slugify/` as a pure-case in the study.

## Why representative

Three reasons:

1. **It is widely deployed.** `tabulate` is one of the most-
   downloaded Python libraries on PyPI (~50M downloads/month);
   the shape of its public API is recognisable to anyone who has
   written a Python CLI.
2. **It is ubiquitous in CLI tools.** Any Python command-line
   program that prints a result grid to the terminal tends to
   reach for `tabulate` (or a hand-rolled clone of the same
   shape); the per-function purity story matters because these
   helpers commonly appear in the rendering layer of tools that
   *do* exercise capabilities elsewhere.
3. **It is the second asymmetry case, in the opposite
   direction.** A PURL-based SBOM for the naive Python has
   nothing to say about this file beyond "depends on Python"
   itself: the only top-level import is `typing`, which is not
   capability-bearing in any sense PURL tooling tracks. Where
   `slugify/` shows pip *over-attributing* (`re` + `unicodedata`
   as opaque dependencies for a pure function), this pair shows
   pip *under-attributing*: silence is not equivalent to a
   per-function purity proof. Capa proves each helper pure
   individually and the SBOM names them.

## Naive Python's PURL SBOM proxy

The top-level import block is `from typing import Iterable`. A
PURL-based SBOM generated by syft / pip-licenses for this file
would list nothing capability-bearing: `typing` is a pure type-
only stdlib module. The PURL output is effectively silent on
this file.

The Capa SBOM names zero capabilities for every helper and the
compiler proves it: a hidden Fs / Env / Net / Unsafe call in any
of `max_int`, `pad_right`, `repeat_char`, `compute_widths`,
`format_row`, `format_separator`, or `tabulate` would be
rejected at type-check time because no such capability is in
scope. The asymmetry this pair makes visible is that PURL's
silence cannot be turned into a positive guarantee, while Capa's
per-function declaration can.

Note on header handling: the Capa version uses an empty
`List<String>` to mean "no header row" rather than carrying an
`Option<List<String>>`; `main` exercises both modes. The
capability-attribution point this pair makes is independent of
that choice.
