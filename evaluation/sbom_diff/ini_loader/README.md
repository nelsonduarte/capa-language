# ini_loader

An INI/config-file loader of the `configparser` (Python stdlib)
and `iniparse` (PyPI) shape.

## What the library does

Reads an INI file (sections delimited by `[name]`, key-value
lines of `key = value`, with `#` and `;` comments and blank
lines skipped), parses it into a nested dict, and returns the
result. The public API is `load_ini(path: str) -> dict[str,
dict[str, str]]`.

## Authority surface

`Fs` only; the parser itself is pure.

## Why representative

Three reasons:

1. **It is universal.** Every config-driven Python application
   reads an INI-shaped file somewhere - either through
   `configparser`, through `iniparse`, or through a hand-rolled
   loader of exactly this shape. The pattern is ubiquitous
   enough that the Python stdlib ships a module for it.
2. **It is the single-capability case.** Unlike `dotenv` (Fs +
   Env) or `config_loader` (Fs + Env + Net), `load_ini` exercises
   one capability. Even so, the per-function split matters: the
   parser is pure and can be tested without any filesystem
   handle, while only the loader needs `Fs`. The signature of
   `parse_ini_text` proves to a reviewer that no file access
   can occur inside it; the type checker enforces that proof.
3. **The PURL SBOM is completely silent.** The naive Python
   imports nothing - no third-party packages, no
   capability-bearing stdlib modules. A PURL-based SBOM
   generated by syft / pip-licenses for this file would list
   ZERO components. The Capa SBOM still attributes `Fs` to
   `load_ini` and `Stdio` to `main`, and proves the pure
   functions cannot touch either. This is the strongest form
   of the SBOM-diff gap: PURL contributes no information at
   all, while Capa attributes per-function.

## Functions

| Function | Signature shape | Declared capabilities |
|---|---|---|
| `parse_section_header` | `(String) -> Option<String>` | *(none)* |
| `parse_kv_line` | `(String) -> Option<KvPair>` | *(none)* |
| `parse_ini_text` | `(String) -> Map<String, Map<String, String>>` | *(none)* |
| `load_ini` | `(Fs, String) -> Result<Map, IoError>` | `Fs` |
| `main` | `(Stdio)` | `Stdio` |

## Naive Python's PURL SBOM proxy

The top-level import block is empty. A PURL-based SBOM
generated by syft / pip-licenses for this file would list
nothing: no third-party packages, no capability-bearing stdlib
modules (the loader uses only the `open` builtin). It would
say nothing about which functions exercise file I/O.

The Capa SBOM names `Fs` per-function on `load_ini` and proves
the pure functions (`parse_section_header`, `parse_kv_line`,
`parse_ini_text`) cannot touch the disk.
