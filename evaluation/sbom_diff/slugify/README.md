# slugify

A URL slug normaliser of the python-slugify shape (~6M downloads
per month on PyPI).

## What the library does

Normalises an arbitrary input string to a URL-safe slug by:

1. Unicode-normalising (NFKD) and stripping combining marks so
   accented characters collapse to their base letters.
2. Lower-casing the result.
3. Replacing any run of non-alphanumeric characters with a
   single `-`.
4. Trimming leading and trailing `-`.

The naive public API is
`slugify(text: str, max_length: int | None = None) -> str`.

## Authority surface

*(none)* - the library is purely a string transformation; this
pair is the asymmetry case in the study.

## Why representative

Three reasons:

1. **It is widely deployed.** python-slugify sits behind a large
   share of CMS, static-site, and admin-panel codebases; the
   shape of its public API is recognisable to anyone who has
   built a Python web service.
2. **It is small enough to compare line-for-line.** The naive
   Python is 30-odd lines and the Capa version splits cleanly
   into three pure helpers plus the composition point, so the
   per-function attribution diff is easy to read end-to-end.
3. **It is the asymmetry case.** A PURL-based SBOM for the
   naive Python lists `re` and `unicodedata` as opaque
   dependencies. Neither module is actually exercising any
   capability surface here (no Fs, no Env, no Net, no Stdio),
   but pip-based tooling has no way to say so: an import is an
   import. The Capa version declares zero capabilities per
   helper AND has the compiler enforce it, so the SBOM-diff for
   this pair shows pip *over-attributing* on one side and Capa
   *machine-verifying purity* on the other.

## Naive Python's PURL SBOM proxy

The top-level import block is `import re` and `import unicodedata`.
A PURL-based SBOM generated by syft / pip-licenses for this file
would list both as stdlib imports, with no per-function
attribution and no signal that the functions are pure.

The Capa SBOM names zero capabilities for every helper and the
compiler proves it: a hidden Fs / Env / Net / Unsafe call in any
of `strip_accents`, `to_slug_chars`, `collapse_dashes`, or
`slugify` would be rejected at type-check time because no such
capability is in scope.

Note on Unicode scope: Capa's `String` builtin does not expose a
Unicode-normaliser equivalent of `unicodedata.normalize("NFKD",
s)`. `strip_accents` in the Capa version substitutes a hand-coded
`replace`-based table covering the common Latin diacritics
(acute, grave, circumflex, tilde, umlaut, cedilla, n-tilde) in
upper and lower case. The capability-attribution point this pair
makes is independent of that table's coverage.
