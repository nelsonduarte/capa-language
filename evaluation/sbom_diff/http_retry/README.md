# http_retry

A fetch-with-exponential-backoff helper of the shape that every
Python HTTP client and standalone retry library exposes
(`urllib3.Retry`, `requests`' `HTTPAdapter` retry, `tenacity`,
`backoff`, `httpx` transport retries).

## What the library does

Fetches the body at a URL, retrying on network failure with an
exponential backoff between attempts:

1. Open the URL over HTTP (Net).
2. On `URLError`, sleep `base_delay * 2 ** attempt` seconds
   before retrying (Clock).
3. After `max_retries` attempts, re-raise the last error.

Exposes a single public function with the signature
`fetch_with_retry(url: str, max_retries: int = 3, base_delay:
float = 1.0) -> str`.

## Authority surface

`Net + Clock` exercised inside one function; signature declares
none of them.

## Why representative

Three reasons:

1. **It is ubiquitous.** Every Python HTTP client ships some
   form of this retry loop; the standalone retry libraries
   (`tenacity`, `backoff`) exist solely to provide it. A
   capability-aware SBOM that handles this pattern correctly
   covers a structural component of essentially every Python
   service that talks to the network.
2. **The shape conflates Net and Clock under one signature.**
   Same structural failure as `config_loader`'s
   `load_config(path)` and `dotenv`'s `load_dotenv(path)`: one
   function exercises two distinct authorities, and the
   signature names neither. A reviewer reading
   `fetch_with_retry(url, max_retries, base_delay)` cannot tell
   which calls open the network and which sleep the process.
3. **It is the first pair in the corpus that exercises Clock.**
   The previous pairs cover Fs, Env, and Net; this one adds
   Clock as a declared per-function authority. It widens the
   axis coverage of the study and lets the harness report on a
   capability that Python has no idiomatic way to attribute (no
   stdlib module is "the clock module" in the way `os` is
   commonly read as "the environment module"; `time.sleep` and
   `time.time` both live in the same module as pure helpers like
   `time.strftime`).

## Functions

| Function | Signature shape | Declared capabilities |
|---|---|---|
| `compute_backoff_seconds` | `(Int, Float) -> Float` | *(none)* |
| `fetch_once` | `(Net, String) -> Result<String, IoError>` | `Net` |
| `wait_backoff` | `(Clock, Float) -> Unit` | `Clock` |
| `fetch_with_retry` | `(Net, Clock, String, Int, Float) -> Result<String, IoError>` | `Net`, `Clock` |
| `main` | `(Stdio)` | `Stdio` |

## Naive Python's PURL SBOM proxy

The top-level import block is `import time` and `import
urllib.request` (plus `from urllib.error import URLError`). A
PURL-based SBOM generated by syft / pip-licenses for this file
would list `urllib.request` and `time` (both capability-bearing
stdlib modules). It would say nothing about which functions
exercise the network vs which exercise the clock; both are
conflated under one signature.

The Capa SBOM names both authorities per-function and proves the
pure function (`compute_backoff_seconds`) cannot touch either.
