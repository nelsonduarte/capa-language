# url_fetch

A `fetch a URL and parse the JSON response` helper of the shape
that every Python HTTP client SDK exposes (`requests.get(url).json()`,
`httpx.get(url).json()`) and that the stdlib docs teach as the
explicit `urllib.request.urlopen(...) + json.loads(...)`
two-step.

## What the library does

Fetches the body at a URL and decodes it as JSON:

1. Validate that the URL is HTTPS with a non-empty host (pure).
2. Open the URL over HTTP (Net).
3. Parse the response body as JSON (pure).
4. Optionally extract a string field with a typed fallback (pure).

Exposes a single public function with the signature
`fetch_json(url: str) -> dict`.

## Authority surface

`Net` exercised in `fetch_text` and `fetch_json`; the URL
validator (`is_https_url`) and the field extractor
(`extract_field`) are pure.

## Why representative

Three reasons:

1. **It is ubiquitous.** Every web client SDK in the Python
   ecosystem ships exactly this GET-and-JSON-parse two-step;
   `requests.get(url).json()` is arguably the most common
   single-line Net surface in modern Python. A
   capability-aware SBOM that handles this pattern correctly
   covers the front door of essentially every Python program
   that talks to a JSON API.
2. **The shape conflates Net and pure parsing under one
   signature.** Same structural failure as `config_loader`'s
   `load_config(path)` and `http_retry`'s `fetch_with_retry`:
   one function opens the network AND parses the body AND
   extracts fields, while the signature names none of it. A
   reviewer reading `fetch_json(url)` cannot tell which parts
   touch the network and which are pure string manipulation; the
   URL validator and field extractor are logically separable
   from the actual fetch but disappear into the same name.
3. **It is the first Net-only pair in the corpus.** `http_retry`
   carries Net + Clock, `log_forwarder` carries Fs + Net, and
   `config_loader` carries Fs + Env + Net. `url_fetch` isolates
   `Net` as the sole authority, widening the cap-axis coverage
   of the study and letting the harness report on Net
   attribution unmuddied by a co-occurring capability.

## Functions

| Function | Signature shape | Declared capabilities |
|---|---|---|
| `is_https_url` | `(String) -> Bool` | *(none)* |
| `extract_field` | `(JsonValue, String, String) -> String` | *(none)* |
| `fetch_text` | `(Net, String) -> Result<String, IoError>` | `Net` |
| `fetch_json` | `(Net, String) -> Result<JsonValue, IoError>` | `Net` |
| `main` | `(Stdio)` | `Stdio` |

## Naive Python's PURL SBOM proxy

The top-level import block is `import urllib.request` and
`import json`. A PURL-based SBOM generated by syft /
pip-licenses for this file would list `urllib.request` and
`json` (one cap-bearing stdlib module, one pure parser). It
would say nothing about which functions exercise the network vs
which are pure parsing and field extraction; all four are
conflated under a single public signature.

The Capa SBOM names `Net` per-function on `fetch_text` and
`fetch_json`, and proves the URL validator (`is_https_url`) and
the field extractor (`extract_field`) cannot touch the network.
