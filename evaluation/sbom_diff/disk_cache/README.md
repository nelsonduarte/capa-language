# disk_cache

A disk cache with TTL of the shape that every Python HTTP client
wrapper and offline-first tool exposes (`requests-cache`,
`diskcache`, `cachetools`' filesystem-backed variants, plus the
hand-rolled `cache_get` / `cache_set` helpers every data-pipeline
codebase ships).

## What the library does

Memoises string-valued computations on disk under a TTL. The
public API is a pair:

1. `cache_get(path, ttl_seconds)`: if the cache file exists and
   its stored timestamp is within `ttl_seconds` of now, return
   the cached value; else return None. Exercises Fs (read the
   file) and Clock (read the wall clock).
2. `cache_set(path, value)`: write the value to the cache file
   together with a fresh timestamp. Exercises Fs (write the
   file) and Clock (read the wall clock to stamp the entry).

The freshness arithmetic itself (`now - stored_ts < ttl`) is
pure given a `(stored_ts, now)` pair; the parser and formatter
for the on-disk shape are pure too.

## Authority surface

`Fs + Clock` exercised in `cache_get` and `cache_set`; the
parser (`parse_cached_entry`), the formatter
(`format_cache_entry`), and the freshness check (`is_fresh`) are
all pure.

## Why representative

Three reasons:

1. **It is ubiquitous.** Every Python HTTP client memoises
   responses on disk somewhere - `requests-cache` and
   `diskcache` between them see ~15M downloads/month on PyPI,
   and the dozens of in-house `cache_get`/`cache_set` helpers
   every data-pipeline and CLI tool ships implement the same
   read-mtime-then-decide pattern. A capability-aware SBOM that
   handles this pattern correctly covers a structural component
   of essentially every Python service that talks to a remote
   API or recomputes anything expensive.
2. **The pure / impure split is surgical.** The freshness
   decision (`now - stored_ts < ttl`) is a pure function of
   `(stored_ts, now, ttl)`; the parser and formatter for the
   on-disk shape are pure functions of their inputs; the ONLY
   impure parts are the file I/O and the single
   `clock.now_secs()` read at the top of `cache_get` and
   `cache_set`. Capa exposes this split surgically (three
   functions are pure, two carry `Fs + Clock`, one carries
   `Stdio`); Python rolls it all into `os` + `time` and two
   signatures that say nothing about which functions read the
   disk or read the clock.
3. **It surfaces a structural asymmetry between the two SBOM
   shapes.** Capa's `Fs` builtin exposes `read`, `write`,
   `exists`, `is_dir`, `mkdir`, `list_dir`, but NO `getmtime`
   or `stat` - the file's mtime is not in the Capa Fs surface
   at all. The naive Python uses `os.path.getmtime` as the
   freshness anchor; the Capa transliteration stores the
   timestamp INSIDE the file (`"<unix_ts>\n<value>"`), which
   is a more disciplined cache format than relying on
   filesystem metadata (the freshness anchor and the cached
   value travel together in one atomic write, and a
   metadata-only attack cannot silently shift the apparent
   staleness of a cached entry). The semantic point - the
   function exercises Fs to read AND Clock to decide - is
   preserved; the on-disk shape is more disciplined.

This pair is the first `Fs + Clock` combination in the corpus
(`rate_limiter` has Clock alone, `ini_loader` has Fs alone,
`log_forwarder` has Fs + Net, `config_loader` has Fs + Env +
Net). Adding it widens the axis-combination coverage of the
study by one cell.

## Functions

| Function | Signature shape | Declared capabilities |
|---|---|---|
| `is_fresh` | `(Float, Float, Float) -> Bool` | *(none)* |
| `parse_cached_entry` | `(String) -> Option<CachedEntry>` | *(none)* |
| `format_cache_entry` | `(Float, String) -> String` | *(none)* |
| `cache_get` | `(Fs, Clock, String, Float) -> Result<Option<String>, IoError>` | `Fs`, `Clock` |
| `cache_set` | `(Fs, Clock, String, String) -> Result<Unit, IoError>` | `Fs`, `Clock` |
| `main` | `(Stdio)` | `Stdio` |

## Naive Python's PURL SBOM proxy

The top-level import block is `import os` and `import time`. A
PURL-based SBOM generated by syft / pip-licenses for this file
would list `os` (a capability-bearing stdlib module that mixes
filesystem access, process control, and environment access under
one name) and `time` (a capability-bearing stdlib module that
mixes the wall-clock and monotonic-clock reads with pure helpers
like `time.strftime`). It would say nothing about which
functions read the disk vs which read the clock; both
authorities are conflated under each of `cache_get` and
`cache_set`, and the pure helper `is_fresh` is invisible to the
PURL view as a separately attributable unit.

The Capa SBOM names both authorities per-function on `cache_get`
and `cache_set`, attributes `Stdio` to `main`, and proves the
pure functions (`is_fresh`, `parse_cached_entry`,
`format_cache_entry`) cannot touch any of them; the freshness
check is pure given a `(stored_ts, now)` pair.
